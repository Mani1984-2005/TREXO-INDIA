# Dead-Stock Reduction Strategy (Module F)
> Generated by `scripts/ml_generate_docs.py` from the actual result files in `reports/ml/` and `models/`. Nothing here is hand-typed from memory.

Queue: `reports/ml/dead_stock_intervention_queue.csv` (907 products; priorities {'P3': 752, 'P4': 108, 'P2': 45, 'P1': 2}).

## Prioritisation (documented, no hidden score)
`priority_points = risk_score x value_weight x evidence_weight` with value weight A=1.0/B=0.6/C=0.3 (rank by historical **sales revenue**, since inventory value is unknown) and evidence weight HIGH=1.0/MEDIUM=0.7/LOW=0.4. Tiers: P1 >= 0.60, P2 >= 0.30, P3 >= 0.10, else P4. These weights are design choices, not fitted values; the owner may change them.

## Action rules
| Situation | Actions |
|---|---|
| Insufficient history | Monitor only - not enough evidence to intervene |
| Critical / confirmed, continuous or intermittent | Stop/pause replenishment; verify physical stock; prioritise selling existing stock; review discontinuation; A/B items escalated to management; pricing/description review if price CV > 0.5 |
| Critical or At-Risk, seasonal/campaign concentrated | Stop/pause purchasing but **review seasonal timing before discounting** |
| At-Risk | Pause new purchasing pending review, reduce quantities, bundle/promote (margin validated first) |
| Slow | Reduce future purchases, no larger orders |
| Class-A with declining demand | Escalate for management review |

Discounts are never recommended blindly: every promotion line is conditioned on margin data, which does not exist. Not producible from current data: transfers (no locations), supplier returns (no contracts), alternative customer segments (CustomerID missing in 25% of rows).

Every queue row contains: product id, description, classification/risk level, risk score, supporting evidence, detected problem, primary intervention, recommended actions, reason, expected direction of impact, expected benefit (qualitative; **no money**), required business inputs, confidence/evidence quality, human-approval flag and evaluation method. `inventory_value_impact` is explicitly `NOT_QUANTIFIABLE_WITHOUT_ON_HAND_AND_UNIT_COST`.

## Evaluation method
After any action compare 60-day sales with the calibrated expectation and with untreated look-alike products (same class and ABC); log outcome. Until pilot data exist, no savings can be claimed.
