# Inventory Intelligence Engine
> Generated by `scripts/retail_generate_docs.py` from actual result files in `reports/ml/retail/` and `models/`.

`src/trexo/ml/retail/inventory/ledger.py`. **Stock is derived only from verified ledger events, never from sales.** The project dataset contains no inventory records, so this engine is verified with unit tests and a SYNTHETIC demo only (`reports/ml/retail/demo_synthetic_*.csv`, every row labelled `SYNTHETIC_FOR_TESTING_ONLY`).

## Event model
`event_id, product_id, location, ts, type, qty (>0), unit_cost, direction (+1/-1 for ADJUSTMENT), expiry_date, unit_price`. Types: OPENING, RECEIPT, RETURN, TRANSFER_IN (stock in); SALE, DAMAGE, TRANSFER_OUT (stock out); ADJUSTMENT (signed by `direction`); RESERVE/RELEASE (reserved stock). Incoming purchase orders are a separate table (`incoming_po_by_product`: open PO quantity, not counted as stock).

## Guarantees (all tested)
- Validation rejects, with a reason and without altering the data: duplicate event ids, missing id/date, non-positive or missing quantity, unknown type, adjustment without direction, negative cost.
- Chronological replay, same-day stock-in before stock-out; **FIFO layers** carry receipt date, unit cost and expiry; every outflow records which layer it consumed (audit trail).
- An outflow exceeding stock is **rejected as NEGATIVE_BALANCE** (not silently clamped); `allow_negative=True` is explicit opt-in.
- Reservations cannot exceed on-hand; `available = on_hand - reserved`.
- Returns re-enter as a new layer dated at the return (conservative: age restarts).
- Missing unit cost stays **unknown** (NaN capital), never zero.
- `reconcile()` compares ledger to a physical count and reports MATCH / DISCREPANCY / NOT_COUNTED; it never auto-corrects.
- Balance identity (in - out = on_hand = sum of layers) tested.

Tests: 9 in `test_inventory_ageing.py`. Not verified: multi-location transfers as a paired operation, expiry batches in real data, performance at shop scale (>1M events).

Missing-field handling: supplier lead time is accepted by the pricing/reorder interfaces but is not part of the ledger; if inventory data is absent the previous sales-based intelligence remains available as a separate capability.
