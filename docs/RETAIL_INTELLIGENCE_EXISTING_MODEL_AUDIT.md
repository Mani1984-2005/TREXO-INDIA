## Reuse decisions
Reused unchanged: data pipeline, features, calibrated recency rule (supplies the *demand risk score* in stock ageing), forecasting (SES default, per-class methods), movement and classification outputs, registry, inference service. No previous artifact was modified or overwritten (new kinds: `pricing`, `bundles`, `customers`, `forecasting_price`).

## What requires improvement / new modules
1. Stock-based capabilities need verified inventory data (new ledger engine; none exists in the project data).
2. Forecasting had no price information -> tested a price-conditional variant (adopted only for scenario forecasts, see `RETAIL_MODEL_EVALUATION.md`).
3. Dead-stock actions were generic -> recovery engine with floors, costs and approval gates.
4. Known limits carried forward: one seasonal cycle, no stock/cost, ML risk models not better than recency.
