## 6. Confirmed usable fields
InvoiceNo, StockCode (string, stripped), Description (text), Quantity, InvoiceDate, UnitPrice, CustomerID (partial), Country (weak). Derived: line value, sale days, weekly/monthly demand, recency, gaps.

## 7. Missing business information (blocks capabilities)
| Missing | Consequence |
|---|---|
| On-hand quantity / snapshots | **No physical dead stock can be confirmed**; all outputs are demand-inactivity indicators |
| Unit cost, margin | No capital tied up, no recoverable value, no discount safety test, ABC uses *sales revenue* not inventory value |
| Receipts / purchase orders / suppliers / MOQ | No reorder quantity, no supplier returns, no procurement backtest |
| Lead times (+ variability) | Reorder point / safety stock cannot be computed from data |
| Location, lifecycle status, returns linkage | No transfers; cannot separate discontinued from stalled |
| Second year of history | Seasonality cannot be estimated, only flagged |

## 8. Reusable components reused
Classification policy (non-product code list, sale definition), `data/processed` movement files as cross-checks, the 41-test audit suite as a regression guard, governance language (UNKNOWN is valid, financial != physical).

## 9. Technical risks
1. One seasonal cycle: Q4 ramp contaminates trend and recency; seasonal items look dead after season.
2. Demand inactivity != dead stock (stated everywhere).
3. Product keys are not case-normalised (unapproved), so case variants are separate products.
4. Final 3 days (2011-12-07..09) cannot be used by weekly forecasting (incomplete week).
5. Repo `.gitignore` excludes `data/processed/*` and `models/*`: trained artifacts and processed data are not versioned by git by default.
