# Feature Engineering
> Generated by `scripts/ml_generate_docs.py` from the actual result files in `reports/ml/` and `models/`. Nothing here is hand-typed from memory.

`build_features(sales, cutoff)` keeps only rows with `Date <= cutoff`. Test `test_features_no_future_leakage` appends 1000x-quantity future rows and asserts features are unchanged. Labels use only `(cutoff, cutoff+60d]` and are never part of features.

## Features (28 computed; 27 used by models)
`history_days, age_days, days_since_last_sale, n_invoices, n_sale_days, total_qty, avg_qty_per_invoice, velocity_per_day, qty_7d, qty_30d, qty_60d, qty_90d, qty_180d, qty_365d, inv_30d, inv_90d, sale_day_share, mean_gap_days, gap_cv, max_gap_days, recency_gap_ratio, monthly_cv, trend_ratio_60, avg_price, price_cv, n_customers, missing_customer_share, log_total_value`

- Windows: quantity sold in the last 7/30/60/90/180/365 days; invoices in 30/90 days.
- Recency/gaps: days since last sale, mean/max gap between sale days, gap CV, `recency_gap_ratio` = recency / own mean gap.
- Variability/trend: CV of up to six 30-day bins; `trend_ratio_60` = (qty last 60d + 1)/(qty prior 60d + 1).
- Price/customer: mean and CV of unit price, distinct customers, share of anonymous sales, log total value.
- **Excluded on purpose:** `history_days` (pure function of cutoff date), calendar month/day-of-week and seasonal indices as model inputs (one cycle observed; month features cannot generalise and would encode position in the year). Seasonality is handled by a *flag* (`SEASONAL_OR_CAMPAIGN_CONCENTRATED`: >=70% of quantity in the best two months).
- Missing-value treatment: single-sale-day products have no gap statistics -> `mean_gap = max_gap = history_days`, `gap_cv = 0` (documented imputation; zero NaN remain - tested).
- Unrequested/unsupported: day-of-week patterns were not used (wholesale invoices are weekday-batched, 6 invoice days/week, no signal beyond demand level); customer concentration limited to distinct-customer count because 24.9% of rows are anonymous.

## Drift check (PSI train vs test)
Max PSI = 2.23 (`reports/ml/dead_stock_feature_drift_psi.csv`). Values > 0.25 indicate material shift; the largest shifts are in cumulative and age features that grow naturally with time - expected for a single-year panel and a reason to retrain whenever data is added.
